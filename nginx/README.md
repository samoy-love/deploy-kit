# nginx

Здесь лежит **источник правды** по конфигурации nginx для всех проектов
samoy.love. Раньше он был только на сервере, а в репозиториях валялись копии
разной степени свежести — их больше нет.

```
sites/      по файлу на домен, ровно то, что подключено в sites-enabled
snippets/   общие куски, включаются из sites/
conf.d/     то, что обязано жить на уровне http (форматы журналов)
```

`conf.d/` появился ради одного правила nginx: `log_format` допустим только в
блоке `http`, а `sites/` — это `server`-блоки. Файлы оттуда ставятся тем же
`nginx-apply.sh`, но без `--enable`: `nginx.conf` подключает каталог целиком.

## Кто что везёт

Конфиг сайта везёт выкатка проекта-владельца: `NGINX_CONF` + `NGINX_DEST` в
описании цели, дальше `nginx-apply.sh` на сервере. Так работают оба пути —
и `dk deploy`, и оба переиспользуемых workflow.

Ничейное везёт `bin/install-server`: `snippets/`, `conf.d/` и один файл из
`sites/` — `000-default.conf`. Это catch-all с `ssl_reject_handshake`, который
закрывает чужие домены, направленные на IP сервера; проекта-владельца у него
нет, потому что он защищает все сайты сразу. Каталог `sites/` целиком команда
не возит намеренно: у остальных файлов владелец есть, и выкладывать их вторым
путём означало бы писать один файл наперегонки с чужим пайплайном.

Файл лежит в `sites/`, а не в `conf.d/`, хотя ничейное — там. Переезд
проверяли на живом наборе: все восемь сайтов поднимали в контейнере с nginx
1.24 обоими способами, поведение совпало — оба `default_server` объявлены
явно, и порядок разбора на выбор `server`-блока не влияет. Выигрыша нет, а в
`conf.d` файл выпал бы из проверки настоящим nginx в CI (она идёт по
`nginx/sites/*.conf`). Подробности — в шапке самого файла.

## Журнал для метрик

`conf.d/samoylove-log-metrics.conf` объявляет формат `samoylove_metrics`, а
конфиги сайтов пишут им второй журнал
`/var/log/nginx/samoylove_metrics.log`. Его читает экспортёр из
[metrics.samoy.love](https://github.com/tr0llex/metrics.samoy.love).

В формате намеренно **нет** IP, User-Agent, Referer и строки запроса: только
домен, метод, путь, код, объём и время ответа. Строку, которой не существует,
невозможно случайно превратить в метку. Поля и их порядок обязаны совпадать с
`format` в конфиге экспортёра — расхождение ничего не ломает, метрики просто
молча перестают появляться.

## Правила

**Один файл — один домен.** Общий конфиг на два сайта уже приводил к тому,
что выкатка лаунчера роняла соседний сайт. Проект правит только свой файл.

**`http2` только формой `listen 443 ssl http2`.** На сервере nginx 1.24,
отдельной директивы `http2 on` там ещё нет — она валит `nginx -t`.

**`add_header` не наследуется.** Как только в `location` появился хоть один
`add_header`, все серверные заголовки в этом `location` перестают отдаваться.
Поэтому заголовки безопасности подключаются сниппетом **в каждом** `location`,
а не один раз на уровне `server`.

**ACME трогать нельзя.** Блок `/.well-known/acme-challenge/` смотрит в каталог,
куда пишет certbot. Если подменить его на каталог релиза, продление сертификата
молча перестанет работать — узнаете через три месяца.

## Как менять

Правки — в этот каталог, дальше выкатка:

```bash
server/nginx-apply.sh --app samoylove \
    --conf nginx/sites/samoy.love.conf \
    --dest /etc/nginx/sites-available/samoy.love.conf --enable
```

Файлы из `conf.d/` ставятся тем же скриптом, но **без** `--enable`: каталог
подключён из `nginx.conf` целиком, включать там нечего.

Скрипт снимает состояние **до** правки, кладёт бэкап, проверяет `nginx -t`
и откатывается сам, если проверка не прошла. Руками в `/etc/nginx` не ходим:
файл на сервере и файл здесь должны совпадать.

## Известные расхождения

Снимок снят с живого сервера как есть, без причёсывания — сначала зафиксировать,
потом нормализовать. Что видно уже сейчас:

- пути разъехались: `/var/www/site/current` у лаунчера, `/var/www/metro/current`
  у метро, `/var/www/samoy.love/current` у главной;
- отдельный `location` для `robots.txt` есть только у лаунчера, у остальных
  файл едет из корня релиза или не едет вовсе;
- `chillhub-launcher.conf` — больше тысячи строк, из них больше половины
  комментарии.

Нормализация — отдельным шагом, чтобы падение можно было связать с одной правкой.
